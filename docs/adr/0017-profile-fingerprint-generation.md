# ADR-0017: Локальная генерация отпечатка при создании профиля

> Статус: генерация и замена реализованы в изолированном локальном срезе; запуск конфигурации на настоящем ShardX не подтверждён
> Дата: 2026-10-16

## Контекст

В ADR-0013 для Phase 2 `identityRef` был временной тестовой ссылкой. Текущая
композиция API уже создаёт конфигурацию отпечатка через адаптер ShardX и
сохраняет её вместе с профилем. Нужно зафиксировать эту границу отдельно от
доказательств реального запуска: обычные проверки не устанавливают и не
запускают движок.

## Решение

1. При создании профиля с `fingerprintEnabled: true` прикладной
   `ProfileCreationService` выдаёт отдельный UUID — уникальный идентификатор —
   для неизменяемой идентичности и вызывает `FingerprintGenerator` до начала
   записи в SQLite.
2. `ShardXFingerprintGenerator` остаётся в инфраструктурном слое. Он запрашивает
   у SDK — комплекта интеграции ShardX — шаблон выбранной целевой платформы,
   создаёт рабочую копию конфигурации и передаёт ID шаблона аппаратному
   рандомизатору; для macOS SDK использует этот ID при выборе модели устройства.
   Затем генератор отдельно рандомизирует версию платформы, проверяет результат
   и возвращает его копию. Типы SDK не выходят в прикладной слой.
3. После успешной генерации профиль и запись идентичности сохраняются одной
   транзакцией SQLite. Ошибка генератора не создаёт ни профиль, ни идентичность;
   тестовая или пустая конфигурация в качестве запасного результата не
   подставляется.
4. При `fingerprintEnabled: false` генератор пропускается, профиль создаётся с
   `identityRef: null`; для этого не требуется установленный ShardX.
5. Обычный `main.ts` создаёт SDK с `autoInstall: false`. Генерация не запускает
   браузер и не устанавливает движок, но SDK проверяет полную локальную
   установку перед чтением библиотеки отпечатков. Если установка отсутствует или
   неполна, ошибка `RUNTIME_NOT_INSTALLED` преобразуется в HTTP 503
   `FINGERPRINT_RUNTIME_NOT_READY`. Остальные ошибки генерации возвращают
   безопасный HTTP 500 `FINGERPRINT_GENERATION_FAILED`.
6. При включении отпечатка у профиля без `identityRef` lifecycle-сервис вызывает
   тот же генератор под блокировкой профиля, но до открытия транзакции SQLite.
   Успешная конфигурация и новое состояние профиля сохраняются атомарно; ошибка
   генерации оставляет профиль без изменений. Выключение сохраняет существующую
   identity, а повторное включение не генерирует её заново.
7. Явная команда `POST /profiles/:profileId/fingerprint/replace` генерирует новую
   identity под блокировкой свободного профиля и атомарно сохраняет запись с
   обновлением `identityRef`. Она сохраняет `fingerprintEnabled`, не меняет и не
   удаляет прежнюю запись; сбой до сохранения не меняет профиль. Маршрут
   зарегистрирован только в композиции, где передан lifecycle-сервис.

### Дополнение — 2026-10-17: целевая платформа

Профиль хранит целевую платформу отпечатка `fingerprintPlatform` со значениями
`Windows`, `macOS` или `Linux`; по умолчанию используется `Windows`, в том числе
для профилей, существовавших до миграции. Это платформа браузерной идентичности,
а не ОС хоста. Генератор получает выбор при создании профиля, повторном включении
отпечатка и его замене, передаёт его SDK и отклоняет несовпадающие значения
`navigator.platform` или, если поле есть, `client_hints.platform` до сохранения.
Для выбора macOS аппаратная рандомизация получает ID выбранного шаблона. Форма
создания профиля позволяет выбрать платформу.

Для уже созданного профиля добавлен маршрут
`PATCH /profiles/:profileId/fingerprint/platform` в композицию с
`BrowserLifecycleService`. Запрос сериализуется той же блокировкой профиля и
отклоняется при активном запуске. Если отпечаток включён, генератор вызывается
для новой платформы до транзакции, а новая identity и платформа сохраняются
атомарно; прежняя identity не изменяется и не удаляется. Если отпечаток выключен,
платформа меняется без генератора, `identityRef` очищается, а старая запись
остаётся в SQLite; включение позже создаёт identity выбранной платформы. Ошибка
генерации не меняет включённый профиль. Выбор прежней платформы — безопасный
повторный выбор не меняет профиль. Проверки используют подменный генератор,
SQLite и runtime; сам браузер не запускается. Селектор существующего профиля
доступен только в интерфейсе с параметром `?fake-runtime`, а маршрут не подключён к обычному
`main.ts`.

## Последствия и границы

- Создание профиля с отпечатком зависит от заранее подготовленной локальной
  среды ShardX; `autoInstall: false` отключает автоматическую установку, а не
  заменяет её.
- Отказ не оставляет профиль-сироту: генерация завершается до транзакции, а
  сохранение двух записей атомарно.
- `fingerprintEnabled: false` остаётся доступным без локальной среды.
- Повторное включение профиля, который ранее существовал без отпечатка, теперь
  тоже зависит от локального генератора; до успешной генерации он остаётся
  выключенным. В обычной композиции runtime lifecycle всё ещё изолирован и не
  подключён к `main.ts`.
- Замена отпечатка не включает выключенный режим и не требует предварительно
  назначенной идентичности; браузер при этом не запускается. Старые неизменяемые
  записи остаются в хранилище, хотя профиль больше на них не ссылается.
- Проверки генератора используют подменённый источник SDK. Они подтверждают
  форму, размер и изоляцию конфигурации, но не успешный запуск настоящего
  браузера с ShardX и не восстановление процесса.
- ADR не принимает цепочку поставки, установку, обновление или реальную
  совместимость ShardX. Эти проверки остаются отдельными воротами D-001,
  D-006 и D-008.

## Рассмотренные альтернативы

- Оставить `test-identity:<profileId>`: ссылка не содержит реальную
  конфигурацию отпечатка и не соответствует текущему сценарию.
- Генерировать отпечаток только при запуске: тогда успешно созданный профиль
  не имел бы конфигурации, подразумеваемой `fingerprintEnabled: true`.
- Автоматически устанавливать ShardX из API создания профиля: это добавило бы
  неявную загрузку и смешало бы создание профиля с отдельной политикой
  установки движка.
