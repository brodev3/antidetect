# ADR-0005: Clean foundation v2 вместо продолжения TypeScript-прототипа

Статус: Accepted

Дата: 2026-08-18

## Контекст

В репозитории одновременно существуют legacy v1, незавершённый TypeScript-рефактор в `packages/*`, частично дублирующий его корневой `src/`, API draft и отдельная целевая архитектура Antidetect v2.

TypeScript-рефактор создавался как мысленный и технический эксперимент вокруг прежнего Bablosoft/Playwright runtime. Он использует Prisma, прежние package boundaries, `Profile.isOpen`, in-memory registry и другие решения, которые расходятся с принятой v2-моделью ShardX, lifecycle runs, durable invariants, recovery и security.

Продолжение этого прототипа создало бы ложную обязанность сохранять его внутренние API, schema и структуру, хотя они не являются требованиями продукта.

## Решение

- Считать прежний TypeScript-рефактор **discarded prototype**, а не основой или промежуточной реализацией v2.
- Реализовывать v2 с clean foundation после согласованного repository checkpoint. Clean foundation не требует отдельного репозитория, но не наследует внутреннюю архитектуру прототипа.
- Не наследовать internal APIs, database schema, package boundaries или старые tests прототипа. Это не является предметом исключения для reuse.
- По умолчанию не переносить prototype code. Допускать исключение только для отдельного небольшого self-contained фрагмента после явного review конкретного кода.
- При review доказать, что фрагмент не связан с Bablosoft/Prisma/устаревшей lifecycle-моделью, не навязывает prototype boundary, соответствует текущим invariants, проще повторного написания и получает заново сформулированные актуальные tests.
- Сохранять прототип и Git history до отдельного решения о физическом удалении или архивировании. Этот ADR не разрешает cleanup, delete или перенос файлов.
- Использовать выводы из прототипа как negative/learning evidence: что не сработало и какие риски должна закрыть v2.

## Причины

- Текущий runtime и persistence direction не совпадают с v2.
- Старые lifecycle assumptions не обеспечивают durable concurrency и recovery.
- `packages/*`, корневой `src/` и API draft уже расходятся между собой.
- Инкрементальный перенос усложнит обучение: будет трудно отличить осознанное v2-решение от случайно унаследованного кода.
- Clean foundation позволяет проверять каждую boundary и invariant небольшими шагами без скрытой backward-compatibility нагрузки.

## Альтернативы

### Продолжить рефактор поверх `packages/*`

Отклонено. Потребует последовательно заменить runtime, persistence, lifecycle, filesystem identity и API boundaries, одновременно сохраняя структуру, которая для v2 не доказала ценности.

### Скопировать полезные пакеты целиком и постепенно очистить

Отклонено. Такой перенос неявно вернёт устаревшие зависимости и assumptions. Повторное использование оценивается только на уровне конкретного небольшого фрагмента.

### Немедленно удалить прототип

Отклонено на текущем checkpoint. Worktree dirty, история ещё не зафиксирована безопасным checkpoint, а удаление требует отдельного подтверждения.

## Последствия

Плюсы:

- однозначная архитектурная отправная точка v2;
- отсутствие обязанности поддерживать prototype internals;
- проще review, тестирование и обучение по небольшим шагам;
- честное разделение legacy/prototype/target.

Ограничения:

- некоторые общие utilities придётся написать заново;
- каждый кандидат на reuse требует отдельного review;
- физическое состояние репозитория останется смешанным до checkpoint и согласованного cleanup.

## Не закрытые этим ADR вопросы

- форма repository checkpoint/ветки;
- дата и способ удаления или архивирования прототипа;
- актуальные версии toolchain;
- результаты обязательного Phase 0 ShardX/Windows spike.
