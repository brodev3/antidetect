# ADR-0013: HTTP-контракт профилей и граница доступа Phase 2

> Статус: принято; Zod-контракты, HTTP-маршруты и bounded search/sort реализованы; режим отпечатка уточнён в тестовом срезе
> Дата: 2026-09-21

## Контекст

В Phase 2 требуется первый сквозной продуктовый сценарий: создать профиль через API — программный интерфейс — и прочитать его после перезапуска. До реализации маршрутов необходимо зафиксировать входные и выходные данные, ограничения списка, ошибки и допустимую на этом этапе границу доступа. Иначе UI, контроллер и repository могут получить разные неявные контракты.

Профиль в этом сценарии является сохраняемой конфигурацией. Он ещё не доказывает готовность ShardX, наличие браузерного процесса или возможность Start/Stop.

## Решение

### Создание

- `POST /profiles` возвращает `201`.
- Клиент передаёт строгий JSON-объект с `displayName` и необязательным `fingerprintEnabled`; по умолчанию поле `true`.
- `displayName` обрезается по краям и после этого должен содержать от 1 до 100 символов.
- Одинаковые отображаемые имена разрешены: идентичностью записи является серверный UUID, а имя остаётся пользовательской подписью.
- Сервер также выдаёт постоянный `profileCode` вида `profile-001`. Это человекочитаемый код для UI и поддержки; он хранится в SQLite, не зависит от текущей страницы, фильтра или сортировки и не заменяет UUID `id` в API-маршрутах и файловых путях.
- Сервер создаёт UUID, UTC timestamps — временные метки — и сохраняет `fingerprintEnabled`. При `true` создаётся явно тестовая ссылка `identityRef` вида `test-identity:<profileId>`; при `false` новая ссылка не создаётся. Это не подтверждает интеграцию с ShardX.

### Чтение одной записи

- `GET /profiles/:profileId` принимает только UUID.
- Существующая запись возвращается с `200`.
- Отсутствующий корректный UUID возвращает `404` и код `PROFILE_NOT_FOUND`.

### Список

- `GET /profiles` использует `limit=50` и `offset=0` по умолчанию.
- `limit` ограничен диапазоном `1..100`; `offset` является неотрицательным safe integer — целым числом, точно представимым в JavaScript.
- Необязательный `search` обрезается по краям и ищет подстроку без учёта регистра только в `displayName`; пустое значение не фильтрует список.
- `sortBy` принимает только `createdAt` или `displayName`, а `sortOrder` — только `asc` или `desc`. По умолчанию используются `createdAt ASC`.
- Порядок стабилен: сначала выбранное поле и направление, затем `id ASC` как tie-breaker — дополнительное поле для однозначного порядка.
- Ответ имеет форму `{ items, nextOffset }`; `nextOffset` равен `null`, когда следующей страницы нет. Точный `total` в этот сценарий не входит.

### Ответ и ошибки

Публичная запись профиля содержит только:

- `id`;
- `profileCode`;
- `displayName`;
- `fingerprintEnabled`;
- `identityRef`;
- `createdAt`;
- `updatedAt`.

`identityRef` может быть `null`, если отпечаток выключен; при `fingerprintEnabled: true` он обязателен. Отдельный `profile.status` не добавляется: состояние запуска хранится в `browser_runs` и не выводится из настроек отпечатка.

Ошибки профильного сценария используют envelope — единую внешнюю оболочку — `{ error: { code, message } }`. Коды ограничены контрактом, а сообщение — безопасным публичным текстом. Неизвестные поля строгих запросов и ответов отклоняются.

### Граница доступа

Для этих трёх ограниченных маршрутов с несекретными metadata — метаданными — применяются ADR-0011, ADR-0014 и ADR-0016: literal loopback, один ожидаемый `Host`, разрешённый `Origin` для изменяющих состояние запросов и валидная memory-only session cookie. Принимается остаточный риск: другой локальный процесс всё ещё может получить сессию через публичный `/session` и подделать разрешённые заголовки.

Для меняющих состояние запросов Origin-проверка по ADR-0016 обязательна и распространяется также на API переключения отпечатка и тестовые команды Start/Stop. Это защита от чужих веб-страниц, а не проверка личности процесса: для MVP доверенная граница проходит по локальному компьютеру, а защита от программ на нём не заявляется.

## Failure paths

- Пустое, пробельное, слишком длинное имя или неизвестное поле отклоняются как `VALIDATION_ERROR` до application service.
- Неверный UUID отклоняется валидацией; корректный UUID без записи возвращает `PROFILE_NOT_FOUND`.
- Неверные, дробные, отрицательные, выходящие за границы или неразрешённые `search`/`sort` параметры отклоняются до SQL-запроса.
- Внутренние пути, состояние SQLite и stack trace не входят в публичную ошибку.

### Сохранение человекочитаемого кода

Миграция `add_profile_codes` добавляет колонку `profiles.profile_code`, заполняет её для уже существующих записей в стабильном порядке `created_at ASC, id ASC`, создаёт уникальный индекс и хранит следующий номер в отдельной однострочной таблице `profile_code_sequence`. Репозиторий увеличивает последовательность и вставляет профиль в одной короткой SQLite-транзакции. Поэтому код не пересчитывается из позиции в списке и не меняется после удаления, фильтрации или сортировки.

Физически добавленная SQLite-колонка остаётся nullable из-за ограничения `ALTER TABLE` на существующей схеме; прикладной repository contract — контракт репозитория — требует выдавать код для каждой новой записи, а уникальный индекс защищает от дубликатов. Прямые записи мимо репозитория не являются поддерживаемым API.

## Границы решения

ADR не реализует ShardX, proxy, delete или CDP. Fake-only переключение отпечатка и Start/Stop не означает подключение production runtime. Более сильная local authentication, process recovery и остальные части требуют отдельных проверяемых решений D-001–D-008/D-010.

## Проверка

Zod-схемы и типы находятся в `packages/contracts`. Tests — проверки — покрывают строгий create-вход, UUID и timestamps ответа, error envelope, значения по умолчанию и границы списка, safe integer, search/sort allowlist, преобразование входной и выходной схемы списка в JSON Schema, реальные SQL-фильтр/сортировку, регистронезависимый поиск кириллицы, status codes, OpenAPI, сохранение после повторного запуска, `Host`/`Origin`, session cookie и отсутствие лишних полей. Более сильная local authentication остаётся отдельной следующей границей.
