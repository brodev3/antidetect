# ADR-0011: базовая политика запросов localhost API

> Статус: принятое базовое решение; session boundary дополнена ADR-0014
> Дата: 2026-09-14

## Контекст

Antidetect v2 — локальный control plane — принимает HTTP-запросы от браузерного UI на loopback-интерфейсе. Один только bind на loopback не защищает API от запросов вредоносной страницы: браузер может отправить запрос на `127.0.0.1`, а DNS rebinding — подмена адреса через DNS — может скрыть фактическое назначение страницы.

Нужно отделить browser-page boundary — границу запросов браузерной страницы — от будущей authentication policy — проверки личности локального клиента. Решение не должно выдавать Host/Origin-проверки за защиту от любого локального процесса.

## Решение

1. `API_HOST` принимает только literal `127.0.0.1` или `::1`. `localhost`, wildcard и внешние адреса отвергаются до вычисления root paths и открытия SQLite/HTTP.
2. Каждый HTTP-запрос обязан иметь ровно один `Host`, совпадающий с настроенным loopback host и портом.
3. `Origin` может отсутствовать для non-browser клиентов. Если он присутствует, он обязан точно совпадать с `http://<configured-loopback-host>:<port>`; `null`, HTTPS и другие host/port запрещены.
4. Нарушение policy получает `403 Forbidden` без передачи запроса в controller.
5. Дублированные `Host` и `Origin` отвергаются независимо от значения.

## Почему не только bind

Bind на `127.0.0.1` или `::1` ограничивает сетевой интерфейс, но не различает same-origin UI и cross-origin страницу. Host/Origin policy снижает риск CSRF-подобных запросов из браузера и DNS rebinding, сохраняя возможность health checks и CLI-клиентов без Origin.

## Ограничения

- Любой локальный процесс всё ещё может сформировать разрешённые заголовки; это не authentication и не authorization.
- Базовая browser session boundary реализована отдельным ADR-0014; она не заменяет защиту от произвольного локального процесса и более сильную policy для чувствительных маршрутов.
- Policy не доказывает, что данные профиля или browser processes восстановлены после аварии; readiness/recovery остаются D-015.

## Проверка

- unit-тесты принимают только literal loopback и корректный порт;
- unit/integration-тесты разрешают loopback `Host` без `Origin` и точный same-origin `Origin`;
- отрицательные тесты отклоняют localhost alias, внешний host, чужой/HTTPS/`null` Origin и внешний `API_HOST`;
- startup integration проверяет, что внешний `API_HOST` отвергается до создания root и открытия HTTP-порта.
