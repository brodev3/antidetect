# ADR-0002: Runner на базе Playwright + fingerprints

Статус: Superseded by [ADR-0004](0004-shardx-runtime-boundary.md)

Дата: 2025-02-06

Автор: @you

> Исторический ADR legacy/Bablosoft runner. `playwright-with-fingerprints` не является целевым runtime v2.

## Контекст

Антидетект-браузер требует стабильного запуска профилей с применением отпечатков (fingerprints) и прокси-настроек. Этот слой должен быть изолирован от доменной логики, но давать предсказуемое API для API/UI.

Требования:

- Поддержка персистентных профилей (отдельные директории)
- Применение fingerprint JSON при запуске
- Настройка прокси и сопутствующих anti-leak параметров
- Минимальная зависимость домена от конкретного движка

## Решение

Выделить слой `runner` и использовать связку:

- `playwright` как базовый движок
- `playwright-with-fingerprints` для подстановки отпечатков
- вспомогательные модули для прокси-проверок (echo/geo)

Runner предоставляет:

- `Runner.configure()` — инициализация движка и папки engine
- `Runner.launch()` — запуск профиля с fingerprint/proxy
- `ProxyChecker` — проверка прокси (echo/geo)
- типы `FingerprintOptions`, `ProxyPluginOptions`, `LaunchOptions`

## Альтернативы

1) Puppeteer + плагины — меньше интеграций с Bablosoft fingerprints.
2) Playwright без fingerprints — не решает задачу антидетекта.
3) Сторонние антидетект SDK — закрытые решения, хуже контроль.

## Последствия

Плюсы:

- Контроль над профилем и настройками запуска
- Чёткое API для домена и UI
- Возможность заменить движок в будущем

Минусы/Риски:

- Зависимость от `playwright-with-fingerprints`
- Требуются ключи и стабильный доступ к сервису fingerprints

## Примечания

Runner остаётся инфраструктурным слоем и не содержит доменной логики.
