# ADR-0006: Допуск Windows 10 без ESU только для изолированной Phase 0

Статус: Accepted — принято

Дата: 2026-08-19

## Контекст

Для одноразового исследования ShardX — сторонней среды выполнения браузера — подготовлена виртуальная машина `Win10` в Hyper-V — системе виртуализации Windows. Пользователь сообщил, что установочный образ Windows 10 был загружен накануне эксперимента. Свежая дата загрузки образа не равна сроку поддержки операционной системы; официальный источник и хеш самого ISO-образа отдельно ещё не проверены.

Автономный аудит внутри виртуальной машины подтвердил Windows 10 Pro 22H2, сборку `19045.6456`, включённые Microsoft Defender и межсетевой экран. Пакет подготовки ESU — расширенных обновлений безопасности — установлен, но ESU Year 1–3 имеют состояние `Unlicensed` — не лицензировано. Эта сборка не получает актуальные исправления Windows 10 без действующей ESU-лицензии.

Phase 0 не является обычной эксплуатацией или production — рабочей средой. Виртуальная машина одноразовая и заранее рассматривается как потенциально полностью скомпрометированная после запуска неизвестного бинарника. На момент принятия решения отсутствие в ней личных данных и проектных секретов ещё требовалось проверить; последующий аудит 19 августа 2026 года закрыл это условие. Цель защитных мер — не сохранить доверие к гостевой Windows, а ограничить воздействие на основную систему и локальную сеть.

## Решение

- Принять отсутствие ESU как явный остаточный риск только для текущего одноразового эксперимента Phase 0.
- Не считать Windows 10 Pro 22H2 `19045.6456` автоматически заблокированной средой для Phase 0, если выполнены все перечисленные ниже условия изоляции.
- Не переносить это исключение на рабочую эксплуатацию, обычное использование браузера, реальные аккаунты, личные данные, постоянные среды, CI — автоматические проверки — или рекомендации пользователям продукта.
- Считать гостевую Windows недоверенной до, во время и после ShardX; успешная работа Defender не меняет эту модель.
- Не объявлять ISO-образ официальным, чистым или безопасным только по дате загрузки. Непроверенное происхождение ISO остаётся задокументированной неопределённостью, но в принятой модели недоверенной одноразовой среды не образует отдельный автоматический запрет.
- До запуска ShardX отдельно проверить источник, цифровую подпись доступных файлов и SHA-256 — криптографический отпечаток — именно загружаемых файлов ShardX.
- Разрешить будущий сетевой доступ и запуск ShardX только после отдельного подтверждения пользователя и закрытия обязательных защитных условий.

## Обязательные условия до ShardX

- отрицательными тестами доказать отсутствие доступа к основной системе, локальным сетям и IPv6;
- проверить отсутствие личных аккаунтов, секретов, пользовательских профилей и подключённых общих ресурсов;
- проверить и по возможности отключить ненужные гостевые службы удалённого доступа;
- подтвердить актуальные обновления основной Windows, Hyper-V и драйверов;
- создать при выключенной виртуальной машине исходную контрольную точку при политике `CheckpointType: ProductionOnly` — без запасного перехода к стандартному механизму;
- настроить контролируемый исходящий доступ без маршрута к основной системе и локальной сети;
- зафиксировать официальный URL — адрес источника, версию, цифровую подпись и SHA-256 ShardX до исполнения;
- использовать только тестовые данные и тестовый прокси без реальных реквизитов.

Невыполнение любого из перечисленных условий возвращает запрет на сетевой запуск ShardX. Изменение модели изоляции, подключение личных данных или использование виртуальной машины как постоянной среды требует нового решения.

## Обязательное действие после эксперимента

После эксперимента откатить виртуальную машину к исходной точке или удалить её по отдельному подтверждению пользователя.

## Причины

- Дата загрузки ISO-образа не свидетельствует о повреждении или устаревшем установочном носителе; Windows 10 22H2 остаётся последней версией Windows 10.
- Цель Phase 0 — исследовать неизвестную среду выполнения в системе, которая изначально не считается доверенной.
- Уже применены отдельный внутренний коммутатор, ограничения сетевого адаптера, отключение перенаправления ресурсов и отсутствие прямого проброса устройств.
- Замена гостевой системы сейчас добавит время и новые изменения, но не устранит сам риск выполнения неизвестного закрытого бинарника.
- Полная изоляция недостижима: даже поддерживаемая гостевая система оставляет остаточный риск уязвимости гипервизора.

## Альтернативы

### Создать новую виртуальную машину Windows 11

Безопаснее с точки зрения поддержки и обновлений операционной системы. Остаётся доступным вариантом, если отрицательные сетевые тесты не пройдут, ShardX не поддержит текущую среду или пользователь решит усилить защиту. Не является обязательным условием текущей Phase 0.

### Законно активировать Windows 10 ESU

Снижает риск известных уязвимостей гостевой Windows, но требует подходящей лицензии и обновления системы. Допустимо, но не обязательно для одноразового эксперимента по этому решению.

### Прекратить Phase 0 на Windows 10

Даёт минимальный риск от гостевой системы, но блокирует проверку ShardX. Не выбрано после явного принятия пользователем остаточного риска.

## Последствия

Плюсы:

- сохраняется уже подготовленная одноразовая среда;
- риск описан явно, а не скрыт за датой загрузки образа;
- работа продолжается малыми проверяемыми шагами;
- результаты остаются применимыми к первичному исследованию ShardX.

Ограничения:

- гостевая Windows может содержать неисправленные уязвимости операционной системы;
- неизвестный бинарник может получить полный контроль внутри гостевой системы;
- виртуализация снижает, но не устраняет риск воздействия на основную систему;
- результаты маркируются `VM-observed` — наблюдалось в виртуальной машине — и не доказывают безопасность рабочей среды;
- это исключение нельзя использовать как общую рекомендацию запускать неизвестные бинарники на неподдерживаемой Windows.

## Вопросы, которые этот ADR сам по себе не закрывает

- фактические результаты отрицательных сетевых тестов — последующей проверкой подтверждены;
- состав и состояние гостевых служб — последующим аудитом подтверждены;
- источник, подпись, хеш и лицензия ShardX;
- точная схема контролируемого исходящего доступа;
- политика уничтожения или отката виртуальной машины после эксперимента.
