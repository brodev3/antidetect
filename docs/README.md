# Карта документации

> Статус: активный индекс<br>
> Последняя ревизия: 2026-09-15
> Авторитетен для: выбора минимального набора контекста

Документация разделяет фактическое состояние, согласованную цель и ещё не проверенные предположения. Это сделано, чтобы новый разработчик не принимал план за готовый код.

## Активные документы

| Документ | Единственная ответственность | Когда читать |
|---|---|---|
| [current-state.md](current-state.md) | Датированный снимок фактического репозитория | Продолжение разработки, аудит, cleanup |
| [product-scope.md](product-scope.md) | Цель продукта, MVP и non-goals | Изменение поведения или scope |
| [architecture.md](architecture.md) | Целевая структура и обязательные инварианты | Lifecycle, persistence, API, security |
| [development-plan.md](development-plan.md) | Очерёдность фаз, gates и acceptance scenarios | Планирование и фиксация прогресса |
| [risk-and-decision-log.md](risk-and-decision-log.md) | Open decisions, hypotheses и active risks | Перед spike или gated-реализацией |
| [adr/](adr/) | Причины уже принятых существенных решений | Только для затрагиваемого решения |
| [spikes/phase-0-shardx.md](spikes/phase-0-shardx.md) | Проверяемые эксперименты ShardX/Windows | Phase 0 и runtime/recovery задачи |

## Статусы утверждений

- **Фактическое состояние** — подтверждено текущим кодом, Git или выполненной проверкой.
- **Принятая цель** — согласованное решение, которое может ещё не быть реализовано.
- **Требует проверки** — vendor/OS/dependency гипотеза без текущего доказательства.
- **Открытое решение** — выбор ещё не сделан; имеет ID в decision log.

## Порядок авторитетности

1. Код, Git, manifests, lockfile и свежие результаты проверок.
2. `current-state.md` для датированного снимка.
3. Активные scope/architecture/plan документы.
4. Accepted ADR.
5. Decision/risk log для незакрытых вопросов.
